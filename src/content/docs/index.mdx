These docs exist to help founders implement the kits correctly once the decision to build is already clear.

If you are still working out the buyer, problem, or MVP boundary, start with [Starting Point](/starting-point) first. If the product direction is clear and you want the default production-ready path, start with [SaaSKit](/docs/saaskit). Use [ProKit](/docs/prokit) only if you intentionally want the lighter engine layer and plan to own more of the structure yourself.

## Start here

- [SaaSKit](/docs/saaskit) for the default founder path, setup sequence, and launch guidance
- [Shared Quick Start](/docs/shared/quick-start) for the fastest path from clone to a working local app
- [Try in 2 minutes](/docs/shared/try-in-2-minutes) for a quick proof-of-life before deeper setup
- [ProKit](/docs/prokit) if you want the narrower infrastructure layer instead of the full SaaSKit path

## What these docs cover

- [Shared setup](/docs/shared) for onboarding, configuration, and launch references that apply across the kits
- [Core features](/docs/features) for shared auth, billing, email, and deployment guidance
- [SaaSKit docs](/docs/saaskit) for the flagship product path most founders should follow
- [ProKit docs](/docs/prokit) for the lighter alternative when you want more control and less built-in product surface

## Use the docs in the right order

1. Clarify the buyer, pain, and scope with [Starting Point](/starting-point)
2. Use the [Production Guide](/learn/production-guide) if you need the implementation sequence before touching setup
3. Choose [SaaSKit](/kits/saaskit) if you want the full production-ready foundation, or [ProKit](/kits/prokit) if you intentionally want the lighter engine layer
4. Use these docs to implement auth, billing, email, deployment, and launch steps without guessing through the setup

## What to read next

- Read [SaaSKit](/docs/saaskit) if you want the default product path
- Read [ProKit](/docs/prokit) if you already know why you want the lighter foundation
- Use [Shared Quick Start](/docs/shared/quick-start) when you are ready to boot the repo locally and move into implementation
