These pages explain the shared product features that matter most once the kit is running: authentication, billing, email, deployment, and the surrounding implementation details.

## Start with the highest-risk features

- [Shared Authentication](./auth.mdx) when you need to confirm sign-up, login, and session handling
- [Shared Billing](./billing.mdx) when pricing, Stripe setup, or checkout is the next blocker
- [Shared Email](./email.mdx) when onboarding, transactional delivery, or lifecycle messages need attention
- [Deployment](./deployment.mdx) when you are preparing the production handoff

## How to use this section

Use these references after the product path is clear and the repository is already running locally. If you still need the general onboarding sequence, go back to [Shared Quick Start](/docs/shared/quick-start). If you need product-level direction, return to [SaaSKit](/docs/saaskit) or [ProKit](/docs/prokit).

## What to do next

- Use [Shared Quick Start](/docs/shared/quick-start) if the local app is not running yet
- Use [SaaSKit](/docs/saaskit) if you want the default production-ready founder path
- Use [ProKit](/docs/prokit) only if you intentionally want the lighter engine layer
