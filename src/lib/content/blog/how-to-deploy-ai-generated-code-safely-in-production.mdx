# The Core Rule: Never Deploy Unreviewed AI Output

AI output must always go through:

1. Structural review  
2. Boundary validation  
3. Billing impact check  
4. Auth impact check  
5. Deployment checklist  

Never deploy directly from a chat window.

---

# 1. Review Discipline Before Merge

Before merging AI-generated code:

Ask:

- Which files were modified?
- Were server/client boundaries changed?
- Was billing logic touched?
- Was authentication touched?
- Were environment variables referenced?

If AI modifies:

- Middleware
- API routes
- Stripe handlers
- Database schema

Slow down.

Review twice.

---

# 2. Protect Billing First

AI frequently introduces billing risk by:

- Skipping webhook verification
- Modifying subscription logic
- Tying features directly to Stripe plan IDs
- Ignoring idempotency

Before deploy:

- Confirm Stripe webhooks still validate signatures
- Confirm billing state updates correctly
- Confirm entitlements still enforced server-side
- Test failed payment flow in staging

If billing is unstable, do not deploy.

# 3. Protect Authentication Boundaries

AI often weakens auth unintentionally.

Before deploy:

- Confirm all protected API routes enforce session validation
- Confirm role checks still exist
- Confirm no client-only guard replaced server enforcement
- Confirm no admin route is publicly accessible

Auth regressions are silent until exploited.

---

# 4. Validate Environment Assumptions

Common AI mistake:

- Introducing new environment variables
- Hardcoding values
- Referencing undefined keys

Before deploy:

- Compare .env.example with production config
- Confirm new variables are defined in all environments
- Confirm secrets are server-only
- Confirm no test keys exist in production

Environment drift breaks deployments.

---

# 5. Test in Staging With Production-Like Conditions

Do not test only locally.

In staging:

- Use production-like database
- Use production-like Stripe mode (test mode with realistic flows)
- Simulate user upgrades
- Simulate failed payments
- Simulate session expiration

Deployment safety requires simulation.

---

# 6. Logging and Monitoring Verification

Before pushing to production:

- Confirm structured logging exists
- Confirm error boundaries are active
- Confirm webhook logs are visible
- Confirm build logs are clean

If you cannot observe failure, you cannot recover from it.

---

# 7. Rollback Plan Before Every Deploy

Ask:

- Can I redeploy previous commit quickly?
- Were database migrations reversible?
- Did this change alter schema?
- Are backups available?

Deployment without rollback plan is gambling.

---

# 8. Staged Deployment Strategy

For larger changes:

- Deploy backend changes first
- Validate server health
- Deploy frontend changes
- Monitor logs for 10–30 minutes
- Confirm billing and auth flows

Avoid massive multi-layer deployments at once.

Small deltas are safer.

---

# 9. AI Deployment Checklist (Copy This)

Before every AI-driven deployment:

- Review changed files
- Validate billing lifecycle
- Validate auth boundaries
- Check environment variables
- Run migrations safely
- Confirm logging active
- Confirm rollback path
- Smoke test critical flows

If any step fails, stop.
