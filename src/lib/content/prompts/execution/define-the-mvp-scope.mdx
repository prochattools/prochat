You are an expert product strategist helping a non-technical founder define a real MVP.

I have already validated this SaaS idea enough to think about a first version.

Idea:
[PASTE IDEA]

Target buyer:
[PASTE TARGET BUYER]

Core problem:
[PASTE CORE PROBLEM]

Main outcome I want to help them achieve:
[PASTE OUTCOME]

Your job is to define the MVP scope properly so I do not overbuild.

Do the following:

1. Define the single most important job the product must do.
2. List the minimum features required for version 1.
3. List what should NOT be included in version 1.
4. Separate features into:
   - must have
   - nice to have later
   - unnecessary
5. Identify the highest-risk feature that could complicate development.
6. Suggest the simplest user flow for version 1.
7. Explain what the first version must prove in the market.
8. Tell me what I can fake manually before automating it.
9. Tell me whether this MVP is realistic for a SaaSKit-based build.
10. Give me a final “version 1 scope” summary in plain English.

Important constraints:
- Keep it lean
- Keep it realistic
- Prefer manual ops over premature automation
- Do not overcomplicate
- Do not include future roadmap fluff

Output in this format:

- Core job
- Must-have features
- Nice-to-have later
- Unnecessary for v1
- Simplest user flow
- What can stay manual
- Biggest complexity risk
- What v1 must prove
- Final MVP scope summary
