# BuildFlow Page Blueprint

Status: secondary/legacy product page plan aligned to ProChat OS strategy.

Last updated: 2026-05-24

## Source of truth

The `mind` repo is canonical.

BuildFlow is subordinate to the ProChat OS strategy.

```text
ProChat OS = flagship
BuildFlow = secondary/legacy project-context application
```

## Goal

Create or maintain a `/buildflow` page that explains BuildFlow without making it the flagship product.

The page should make three things clear:

1. BuildFlow remains useful.
2. BuildFlow is not the company strategy.
3. ProChat OS is the flagship Agentic Workflow OS.

## Correct positioning

BuildFlow is a project-context and safe-execution product for AI-assisted work.

It can help with:

- repo context
- notes and docs context
- planning
- safe file operations
- handoff prompts
- implementation support

It should not be described as:

- the flagship
- the main ProChat product
- the top of the funnel
- the replacement for ProChat OS
- the place where ProChat OS ideas are being folded

## Relationship to ProChat OS

BuildFlow may later inform or contribute modules to ProChat OS, especially around:

- CLI workflows
- safe repo operations
- support bundles
- local project context
- execution handoffs

But the business, website, roadmap, and implementation priority remains ProChat OS.

## Page route

```text
/buildflow
```

## Page purpose

The page should preserve BuildFlow context for users who arrive through old links, but route strategic attention back to ProChat OS.

1. Hero

## Acceptance criteria

- Does not call BuildFlow the flagship.
- Does not make BuildFlow the homepage/product strategy.
- Clearly says ProChat OS is leading.
- Uses ProChat OS as the primary CTA.
- Keeps BuildFlow as a useful secondary/legacy product.
