## Approved direction

The film uses a combination of:

- primarily abstract memory visualization;
- indirect human presence;
- no visible character-led narrative;
- one continuous camera journey;
- a clear first frame that already communicates memory, intelligence, ownership, and continuity;
- progressive explanation through scrolling rather than an initially ambiguous visual.

The sequence must feel like **Memory Intelligence**, not generic artificial intelligence.

## Master visual identity

### Environment

- dark, deep spatial field;
- calm atmospheric depth;
- no visible room or conventional interface dominating the composition;
- subtle traces of rigid legacy interface geometry may appear briefly and dissolve;
- ample negative space reserved for webpage text overlays.

### Materials

- fine luminous memory threads;
- translucent glass-like memory planes or cards;
- soft particulate evidence fragments;
- restrained metallic or mineral accents where structure becomes durable;
- no glossy consumer-electronics product render;
- no medical anatomy;
- no science-fiction HUD.

### Lighting

- low-key cinematic lighting;
- restrained bloom;
- localized highlights that indicate relevance, provenance, or current applicability;
- historical material softer and less saturated;
- current context sharper and more luminous;
- possible future paths visible but unresolved.

### Initial palette hypothesis

- near-black or midnight background;
- deep burgundy and violet atmospheric depth;
- pale warm-neutral memory nodes;
- limited cool cyan only where needed for contrast or uncertain context;
- subtle amber or warm-white signal for approved/current memory;
- no rainbow data visualization;
- no dominant cyberpunk blue.

### Human presence

Humanity is implied through:

- organic timing and movement;
- a subtle profile-like negative space or silhouette that briefly emerges from the memory field;
- camera scale suggesting movement through one’s own memory;
- gestures in the motion of threads rather than literal hands or faces.

A literal half-human/half-machine brain is not the final brand image.

## Camera rules

1. The camera moves continuously and deliberately.
2. No abrupt cuts inside the preferred single-shot generation.
3. Motion begins slowly, accelerates slightly during structure formation, then becomes calm again.
4. Depth reveals meaning: moving closer should expose sources, relationships, confidence, and history.
5. Camera movement must preserve negative space for HTML overlays.
6. Avoid spinning, roller-coaster movement, or disorienting parallax.
7. The final camera position must be usable as a stable CTA frame.
8. Forward and reverse playback must both remain visually coherent because users may scroll upward.

## Approved 12-second storyboard

### Beat 1 — Memory already exists


#### Visual

The first frame already shows a quiet field of fine memory threads and translucent memory units suspended in depth. The system is not chaotic, but its relationships are only partially visible.

Faint remnants of rigid interface geometry sit deep in the background and begin dissolving.

#### Meaning

- memory already exists in the user’s work;
- it is fragmented and only partly connected;
- ProChat Memory is immediately recognizable as a memory system rather than a generic AI product.

## Continuity requirements

The following elements must remain visually consistent throughout the sequence:

- thread thickness language;
- memory-card material;
- palette;
- lighting direction;
- focal depth;
- camera lens character;
- particle density;
- importance/relevance encoding;
- historical/current/future visual distinction.

No new visual metaphor should appear after Beat 2 unless introduced through an existing element transforming naturally.

## Semantic encoding


## Negative guidance

The generated sequence must avoid:

- generic glowing neural networks;
- literal anatomical brains;
- half-human cyborg faces as the primary motif;
- robots;
- sci-fi control rooms;
- floating code rain;
- Matrix-style imagery;
- dense dashboards;
- readable generated text;
- holographic HUD overlays;
- rapid camera spins;
- unexplained explosions of particles;
- neon rainbow colors;
- sinister surveillance imagery;
- loss-of-control symbolism;
- a recommendation being accepted automatically;
- closed proprietary-container symbolism;
- obvious copies of the supplied references.

## Responsive composition

### Desktop

- cinematic wide field;
- overlay copy aligned to a stable negative-space zone;
- central memory action may move across the frame but must not pass behind critical text;
- CTA remains visible in the final stable composition.

### Mobile

Do not simply crop the desktop film.

A mobile derivative may require:

- repositioned focal action;
- reduced particle density;
- fewer simultaneously visible memory cards;
- vertically organized thread flow;
- a different negative-space zone;
- shorter overlay copy;
- static or stepped fallback on constrained devices.

## Seedance production strategy

### Preferred first attempt

Generate one continuous 12-second shot using:

- the approved first-frame concept;
- the approved final-frame concept;
- the six-beat transformation described above;
- reference images selected for material, motion, and spatial depth—not for copying composition;
- strong continuity constraints;
- no generated text.

### Fallback

If one-shot continuity fails, split into two six-second clips:

```text
Clip A: Beats 1–3
Clip B: Beats 4–6
```

Design the join around the moment the camera enters the provenance thread, using matching camera direction, palette, and focal geometry.

## Post-production plan

1. Select the generation with the clearest semantic transformation, not merely the most spectacular image.
2. Remove unstable frames or visual artifacts.
3. Stabilize exposure, palette, and motion.
4. Ensure first and final frames hold cleanly.
5. Create a seamless 12-second master.
6. Export a high-quality archival master.
7. Extract 288 source frames for review.
8. Select or resample approximately 144 frames for the first web prototype.
9. Generate responsive AVIF/WebP variants.
10. Prototype loading, memory use, and scroll behavior before finalizing frame count.
