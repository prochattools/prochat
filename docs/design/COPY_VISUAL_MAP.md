# ProChat Copy-to-Visual Map

**Status:** canonical page-story mapping  
**Authority:** canonical Mind copy, `docs/design/VISUAL_LANGUAGE.md`

## Purpose

This document prevents copy and visuals from drifting apart. Each important proposition must have a visual treatment that adds mechanism, evidence, sequence, or boundary.

## Philosophy page

Use restrained editorial diagrams rather than product demos for every paragraph.

Required visual moments:

- useful work leaves useful knowledge;
- Memory → Evidence → Human review → AI use;
- evidence hierarchy;
- bounded assistance;
- readable local foundations;
- two products, one philosophy.

## About page

Visuals should be factual and restrained:

- founder portrait or authentic work context if approved;
- short origin timeline;
- QA experience leading to the first Memory edition;
- company/product architecture.

Do not use lifestyle stock photography or imply a large team.

## Contact, Privacy, Terms, and documentation pages

These pages prioritize reading, trust, and task completion.

Use:

- clear form state;
- contact-path routing;
- version and effective-date metadata;
- local-versus-provider boundary diagrams where legally useful;
- table of contents;
- readable typography;
- minimal motion.

Do not force cinematic treatment onto legal or utility pages.

## Acceptance rule

A visual is required only when it improves understanding. If the visual adds no mechanism, evidence, boundary, or comparison, use excellent typography and layout instead.
